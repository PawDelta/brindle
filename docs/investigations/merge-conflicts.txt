Method notes
  - Day buckets: New York local time, computed as date(created_at,'unixepoch','-5 hours')
    for inbox rows (EST after 2026-11-01). Git days use commit author dates (%ad).
  - Inbox predicates are disjoint unless stated:
      P_feature: body LIKE '[brindle pipeline]%was approved, but merging%conflicts in:%'
      P_refused: body LIKE '[brindle pipeline]%approved but couldn''t be merged%conflicts in%'
      P_sync:    body LIKE 'origin/main has %conflicts in:%'
    The overlap column is body LIKE '%overlap%' and includes some quoted prose (for
    example reviewer text), so it is an upper bound. The broad column is the same
    predicate ANDed with a broad glob (src/**, app/**, tests/**), so broad <= overlap by construction.
  - Git predicate: merge commits whose message body contains "# Conflicts:"
    (git's list of conflicting paths), across all refs.
  - I could not read the main checkout (/Users/hannahlerner/Projects/brindle), by rule.
    Anything that lives only there is marked UNVERIFIED.

Why the coordinator didn't prevent the recorded collisions (ranked):

(a) Session branches hide work from the overlap check. Since 09582ca9 (11-02,
    "session branch counts as landed"), _reported_unmerged (tasks.py ~L105-132)
    treats a reported branch as landed when it merges into its own session base,
    not only into main. So a worker whose work sits in brindle/session-8 is no
    longer a clash for anyone, even though main does not have it. This is the
    mechanism that makes session branches opaque. Confirmed in the diff.
    Note that _reported_unmerged's merged check still runs only for reported
    tasks, and the changed-file scan of reported worktrees now runs only when the
    new task declares files (tasks.py ~L211, "if files else []").

(b) Warnings don't block. The held-worker warnings are generated through
    _held (tasks.py ~L175), with the outcome set by overlap_mode (tasks.py ~L291):
    "block", "warn" or "queue". Which mode is in force depends on precedence (see
    section 3). When the mode is warn, a clash is reported and the task starts,
    so the warning is informational and gets ignored.

(c) Broad globs make every warning fire. _glob_match (tasks.py ~L59-80) uses
    fnmatch in both directions, and fnmatch lets `*` cross `/`. So `src/**` and
    `app/**` match every file under the tree. The 11-06 to 11-10 warnings are
    80-90% broad-glob hits (see the broad column above).

(d) Shared test files. Most listed collisions are test files, and the
    coordinator matches declared globs such as tests/**, so concurrent features
    collide on the same tests. Repeated files: tests/test_visuals.py (2),
    tests/test_daemon_api.py (2), Sidebar.test.tsx (3), InboxScreen.test.tsx,
    GoalPanel.test.tsx, ReviewSheet.test.tsx.

(e) The forecast ignores work that has already reported. conflict_forecast
    (tasks.py ~L338-L355) uses running_tasks only, so a branch drops out of the
    forecast when its worker reports, which is when it gets merged. Not changed
    since 10-19.

(f) Minor: conflict_notices rows (39 now) cascade with their workspace (db.py
    ~L318), so a removed workspace re-warns on the next turn.

Ranking, most to least supported:
  1. Work landed only in a session branch is invisible to the coordinator
     (a). Confirmed in the 11-02 diff; the size of its effect is not measured.
  2. Warnings are not enforced and fire on broad globs (b, c). Strongly
     supported by the counts.
  3. Shared test files as the collision surface (d). Supported by the file lists.
  4. The forecast ignores reported work (e). Confirmed in code; contribution not measured.
  5. Session-8 / governance overlap is a risk (29 shared files, one prediction),
     not an observed cause of recorded conflicts.
  6. Minor: notice cascade (f).

Effective overlap mode, and precedence (UNVERIFIED in part):
  - src/brindle/config.py load_repo_config (~L435-L467) reads, for each key,
    local (.brindle/config.local.json) first, then shared (.brindle/config.json),
    then the person's ~/.brindle/config.json. The first source that has the key
    wins. "overlap" is in that list (~L455).
  - The shared .brindle/config.json in this worktree has no overlap key, so the
    default applies (overlap_mode: "block" within a session, "queue" across sessions).
  - Reviewer round 1 reports that the main checkout's .brindle/config.local.json
    sets overlap to "warn". I could not read that file (main checkout is off-limits
    to me), so this is UNVERIFIED by me. If it is correct, it explains the
    "allowed to start with a warning" messages, and it means that setting "block"
    in the shared config would not override it.
  - The held-worker warnings in the notices describe work already reported but not
    merged, not holder-less intents, consistent with the code above.


4. PROPOSED FIXES (CONCRETE)
----------------------------

1. Make work that has landed only in a session branch visible to the coordinator
   (fixes 1a). Revert the "session base counts as landed" test in
   _reported_unmerged, or keep it but still compare that branch's changed files
   against new tasks. Test: a task on files held only by a session-8 branch must still
   warn. Target: tasks.py _reported_unmerged, find_clash.

2. Override the effective mode where it is actually set. Check
   .brindle/config.local.json and ~/.brindle/config.json for "overlap" first, then
   set the intended value there (or remove the local override). Setting it only in
   the shared file does not override a local value (config.py ~L435-L467).

3. Narrow the broad globs (fixes c). Count the repo files each glob matches. A
   pattern matching more than N files, or a bare `src/**`, is reported as
   "broad: N files" and compared with changed files of other branches, not
   matched against every path. Test: `src/**` does not match `src/brindle/tasks.py`
   unless that file is in another branch's diff.

4. Dedupe warnings per (task, holder, shared files) instead of per assign.

5. Cap session-branch divergence (fixes 1, supervisor's lead). Track commits
   ahead of origin/main and days since the last sync per session branch. Past a
   threshold, prompt a PR to main and absorb main before new merges. Hook point:
   session_sync.py Drift (~L50) and the "behind" outcome (~L252).

6. Let conflict_forecast include reported-but-unmerged work (fixes e), not only
   running tasks (tasks.py ~L338-L355).

7. Split the hot test files (fixes d): new feature tests in new per-feature
   modules. Start with test_visuals.py, test_daemon_api.py and Sidebar.test.tsx.

8. Keep warned pairs past workspace removal (fixes f): store them in the merges
   ledger, not only the cascading conflict_notices table.

9. Add conflict and overlap event kinds to the events table. Today it has none,
   which is why these counts come from inbox text.
