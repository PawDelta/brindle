3. WHY THE COORDINATOR DIDN'T PREVENT THEM
------------------------------------------

Recent changes on the overlap path (git log on src/brindle/tasks.py, coordinator.py, config.py):

  09582ca9  2026-11-02  Overlap check: no fetch, cached cheap merged check, session branch counts as landed
            _reported_unmerged (tasks.py ~L105-132) treats work merged into its session base as
            landed, not only work merged into main. The changed-file scan of reported worktrees now
            runs only when the new task declares files (~L211).
  6f87124a  2026-11-02  queued tasks count for overlap
            adds _queued_overlap (tasks.py ~L192-208): declared files of queued and starting tasks
            now clash.
  6817fa3a  2026-11-09  Enable coordinator by default for entitled accounts
            config.py coordinator default becomes None ("on when the plan includes it");
            coordinator.py changed (19 lines). Coordinator advice appears from 11-09 (inbox 20168).
  12bed04e  2026-10-19  shared knowledge layer and coordinator (#205): the original design.

Ranked causes:

(a) Session-branch work is invisible to the overlap check. Since 09582ca9, work merged into its
    session base counts as landed in _reported_unmerged, so a worker's changes in a session
    branch no longer clash with other tasks, though main does not have them. Confirmed in the
    diff. Its effect on the recorded conflicts is not measured.

(b) Warnings are not enforced, and broad globs make most of them fire. _held (tasks.py ~L175)
    reports a clash; overlap_mode (tasks.py ~L291) decides whether it blocks, warns or queues.
    _glob_match (tasks.py ~L59-80) uses fnmatch in both directions, and fnmatch lets `*` cross
    `/`, so `src/**` and `app/**` match every file in those trees. Broad is 84-100% of overlap
    on each day from 11-06 (11-10: 189 of 226).

(c) Shared test files. Of the 13 feature notices and 5 incidents, most name a test file (for
    example Sidebar.test.tsx on three notices, tests/test_daemon_api.py on two, tests/test_visuals.py
    on two incidents). The coordinator matches declared globs such as tests/**, so concurrent
    features collide on the same tests.

(d) The conflict forecast ignores reported work. conflict_forecast (tasks.py ~L338-355) uses
    running_tasks only, so a branch drops out when its worker reports, which is when it is
    merged. Not changed since 10-19.

(e) Minor: conflict_notices rows (39 now) cascade with their workspace (db.py ~L318), so removal
    re-warns on the next turn.

Ranking, most to least supported:
  1. Session-branch work is hidden from overlap checks (a). Confirmed in code.
  2. Warnings are unenforced and broad-glob noise (b). Supported by the counts.
  3. Shared test files as the collision surface (c). Supported by the file lists.
  4. The forecast ignores reported work (d). Confirmed in code; contribution not measured.
  5. Session-8 / governance overlap is a risk, not a recorded cause.
  6. Notice cascade (e), minor.


4. WHAT CHANGED, AND THE EFFECTIVE OVERLAP MODE
------------------------------------------------

Effective mode (current, with attribution):
  - src/brindle/config.py load_repo_config (~L435-467) reads each key from the local file
    (.brindle/config.local.json) first, then the shared file (.brindle/config.json), then
    ~/.brindle/config.json. The first source with the key wins; "overlap" is in that list (~L455).
  - The reviewer (round 2) reports that the main checkout's .brindle/config.local.json sets
    overlap = "warn". I could not read it (the main checkout is off-limits to me), so this is
    attributed to the reviewer, not verified by me. If correct, the current effective mode is
    "warn", and setting "block" in the shared config would not override it.
  - The shared .brindle/config.json in this worktree has no overlap key. The local file takes
    precedence, so this does not mean the default applies in the repo. The default (block within
    a session, queue across sessions, tasks.py ~L291 and config.py ~L183) applies only when no
    local or user file sets it.

Historical settings: unknown. The local file is untracked, so its history is not available.

Fixes:
  1. Make the work hidden by 09582ca9 visible: keep "landed" only when merged into main, or keep
     the session-base rule but still compare that branch's changed files against new tasks.
     Test: a task on files held only by a session-8 branch still warns. Target: tasks.py
     _reported_unmerged and find_clash.
  2. Set the intended overlap value where it takes effect: the local file (and the user file if
     the person wants it everywhere), then remove conflicting values.
  3. Narrow broad globs: count the repo files each glob matches; a pattern matching more than N
     files, or a bare `src/**`, is reported as "broad: N files" and compared with other branches'
     changed files. Test: `src/**` does not match `src/brindle/tasks.py` unless that file is in
     another branch's diff.
  4. Dedupe warnings per (task, holder, shared files) instead of per assign.
  5. Cap session-branch divergence: track commits ahead of origin/main and days since the last
     sync per session branch; past a threshold, prompt a PR to main and absorb main before new
     merges. Hook point: session_sync.py Drift (~L50) and the "behind" outcome (~L252).
  6. Let conflict_forecast include reported-but-unmerged work (tasks.py ~L338-355).
  7. Split the hot test files: new feature tests in new per-feature modules. Start with
     test_visuals.py, test_daemon_api.py and Sidebar.test.tsx.
  8. Keep warned pairs past workspace removal, in the merges ledger rather than only in the
     cascading conflict_notices table.
  9. Add conflict and overlap event kinds to the events table; today it has none, so these counts
     come from inbox text and are subject to retention.
