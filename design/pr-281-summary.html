What changed underneath

Behavior changes

New

Presets as ordinary rules. Choosing a preset seeds editable rules. The engine still synthesizes a few safety decisions (shell-syntax ask, blocks for unreadable policy) that aren't removable rows, but the old git push and .env denies become removable preset rules.

New

Saved actions. Allows and denies saved from the Inbox keep their scope, the original request and an expiry. A saved allow applies only within the current rule's limits; deny rules beat saved allows; expired ones never apply.

New

Generalized, grouped requests. Pushes are keyed on where they land ("into the default branch from any branch"), file writes on their folder, commands on their family, tools on a single tool by default. A request a saved allow covers can skip the Inbox, but only within the rule's current limits and provider enforcement.

New

Read-only commands run. grep, cat, ls, git log and similar run once brindle has checked their syntax, programs, options and the files they read, and only when no stronger restriction applies. Secure omits the pipeline allow and its broad bash ask covers even git and check commands; anything brindle can't fully parse goes through the rules.

Changed

Every tool is checked. Claude's pre-tool check now covers file, web and MCP tools, not only shell commands, for every provider.

Changed

Pushes into release and release/* ask every time, in every preset. Ported from main as a removable preset rule; saved allows can't settle them. Pushes into the default branch ask too, but a saved approval can last (up to forever in Autonomous, 15 minutes in Secure).

Migrated

0.4.7 settings convert on first launch. Lenient → Permissive, Balanced → Standard, Strict → Secure (none → Autonomous); custom rules become rules; remembered pushes and grants become saved actions with their scope, remote, owner and remaining uses. Old files are left in place.

Removed

The parallel 0.4.7 system: its rule editor (PermissionRules.tsx, permission_editor.py), Lenient/Balanced/Strict presets, daemon-held grants (daemon/grants.py) and their routes.

Removed

permission_essentials. Its read-only allowance moved into the main rules. An old config that still sets it loads fine and the key is ignored. permission_policy is the only switch; with no explicit setting it defaults on only with the learned-rules license capability.

Fixed during review

Holes closed before merge

Security

File, web and MCP tools skipped the new checks in a launched CLI.

Security

A saved deny on pushes into the default branch could be bypassed with a wildcard refspec.

Security

A push naming several branches could slip into release/* without asking.

Security

sort --out= and --compress-prog= were treated as read-only.

Usability

git push origin HEAD, bare git push and multi-branch pushes can now be approved once for exactly that request.
