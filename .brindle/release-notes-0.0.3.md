brindle 0.0.3 adds multi-repo sessions, brings back the brindle CI client, and makes brindle hold up when tmux stops answering.

- **Multi-repo sessions (brindle Pro).** One session can work across several repos. Attach them with `brindle repo add <path> [--name alias]`, and list or remove them with `brindle repo ls` and `brindle repo rm`. The supervisor hands work to workers in any attached repo. Each repo keeps its own checks, reviews and merges. Task dependencies work across repos, and a milestone can run its check in another repo (`check@alias: …`).
- **The brindle CI client (brindle Team).** brindle CI runs on PawDelta's hosted service, and `brindle ci` is its client. `brindle ci init` sets up a repo in one command; model keys go into GitHub's own secret prompt, and brindle never sees them. `brindle ci start`, `run` and `report` are what the generated GitHub Actions workflow runs; each run stays within the time and token limits the server sets and reports what it used. `brindle ci doctor` shows which agent CLIs and keys a CI job has. A run triggered from a Jira ticket whose text has expired on the server now ends cleanly with a message, instead of failing the workflow.
- **Sign-in checks in `brindle doctor`.** For each installed agent CLI (Claude Code, Codex, Antigravity), `brindle doctor` shows how it's signed in and whether a quota limit is in effect. It names a key's environment variable, never its value.
- **Antigravity sign-in.** Antigravity works with `GEMINI_API_KEY`. A worker whose Antigravity is signed out is refused with a clear message instead of sitting on its login screen.
- **tmux hangs no longer freeze brindle.** Every tmux call now times out (30s, or `BRINDLE_TMUX_TIMEOUT`) with a one-line explanation. Cleanup never treats a hung or different tmux server as a sign that agents have died, and brindle never kills your default tmux server. Starting brindle inside a tmux pane switches to the session instead of nesting a client, even when `TMUX` is unset.

Upgrade with `uv tool upgrade brindle`, then restart running sessions to pick up the new code.
